# SDD-001 · Fundaciones · aceptación

Deben aprobarse todos los criterios aplicables. El resultado por entorno se registra con revisión, hora, credencial identificada por rol y evidencia saneada.

### AC001-01

**Inventario de capacidades / R001-01.** Cada capacidad obligatoria tiene referencia oficial y un procedimiento verificable para el sitio. Evidencia en `CT001-01`.

### AC001-02

**Base tipada y build reproducible / R001-02.** Una instalación limpia supera chequeos y produce recursos válidos para el manifest. Evidencia en `CT001-02`.

### AC001-03

**Contexto confiable / R001-03.** Una sesión válida obtiene respuesta reducida. Una identidad inventada no cambia a quién devuelve el resolver. Evidencia en `CT001-03`.

### AC001-04

**Registro seguro y observabilidad / R001-04.** Una falla forzada genera correlación consultable. El cliente carece de stack y de secretos. Evidencia en `CT001-04`.

### AC001-05

**Humo Jira development / R001-05.** La página real carga, resuelve el proyecto y deniega un perfil no autorizado según el contrato activo. Evidencia en `CT001-05`.
